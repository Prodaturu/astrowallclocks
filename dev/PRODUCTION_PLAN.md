# Production deployment gate (prepare only)

1. **Approve the design and staging candidate.** Review the local URLs and screenshots. Rebuild the pinned Easebuzz package from official 5.8.0 source. Deploy it to staging first, retaining dummy settings and outbound blocks. Run the synthetic commerce, callback, recovery, account, mobile, and shipping checks. Confirm the Transaction V2 response shape and `testdashboard.easebuzz.in` route with Easebuzz before relying on automated recovery.
2. **Snapshot production before any cutover.** Export production MySQL including HPOS tables and verify the archive, and archive WordPress files including uploads, themes, plugins, and configuration. Record the current theme, plugin states, WooCommerce settings, routes, certificate status, and a restoration command. Keep backups outside the public document root and restrict access. Never copy staging orders or customers into production.
3. **Deploy the approved theme only.** Copy tested theme files, activate the theme during a low-traffic window, and leave WooCommerce, Razorpay, COD, Shiprocket, production MySQL, checkout, and historical orders in place. Verify homepage, product, cart, checkout, account, tracking, SEO routes, HTTPS, checkout totals, and production error logs. Restore the previous theme immediately if storefront or checkout fails.
4. **Install Easebuzz disabled.** Install the reviewed, hash-pinned package and verify its integrity, PHP/WooCommerce/HPOS compatibility, exact callback POST route, and a working scheduled-task runner. Do not change the existing merchant webhook. Keep it unavailable to ordinary customers.
5. **Controlled payment gate, requiring separate approval.** The authorized administrator enters live Key and Salt through production WooCommerce admin only. Restrict Easebuzz checkout to the designated tester, keep Razorpay and COD available, and allow only Easebuzz's required payment and transaction-lookup hosts. The client makes one legitimate purchase only after explicit approval. Match the WooCommerce order and transaction ID, amount, merchant key, status, and Easebuzz dashboard record; verify no duplicate stock decrement, email, or Shiprocket booking. Refund through Easebuzz if permitted and record the fee. Restore the disabled gateway and outbound restrictions immediately if any check fails.
6. **Release or roll back.** Enable Easebuzz for ordinary customers only after the controlled transaction and recovery path are confirmed. If the theme fails, revert the theme files and activation only. If the gateway fails, disable Easebuzz and restore Razorpay checkout. Do not restore an old database snapshot over newly created production orders; use the snapshot only for selective recovery with order-by-order reconciliation. Monitor fresh orders, stock, payment status, checkout errors, and Shiprocket handoff after release.
